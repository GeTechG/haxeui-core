## Why
No version of the OpenSpec CLI is fixed anywhere: agents used whatever global `openspec` was installed, and that install is gone. The repository has no OpenSpec skills, so changes were written by hand — none of the six archived changes has a `.openspec.yaml`. Nothing checks OpenSpec at all: CI runs only `commit-kinds`, and `openspec validate --all --strict` of 1.16.0 already fails on three main specs with a requirement longer than 500 characters. `openspec/config.yaml` holds only `context`, so no authoring rule reaches the artifacts.

## What Changes
- `openspec/cli.pin` names the CLI version (`1.16.0`). The machine runs a global install of that version; CI runs it through `npm exec`. A bump raises the global install, changes the pin and regenerates the skills in one commit; `AGENTS.md` says so.
- The OpenSpec skills (propose, explore, continue, apply, update, ff, sync, archive, bulk-archive, verify) are generated by the pinned CLI into `.claude/skills/openspec-*` and `.agents/skills/openspec-*` and committed.
- `openspec/check.sh`, run by a new CI job and before every push: `openspec validate --all --strict`; no main spec whose Purpose starts with `TBD - created by archiving change`; a `.openspec.yaml` in every active change; the skills' `generatedBy` equal to the pin; no unchecked task in an archived change unless it is `[human]`.
- `openspec/config.yaml` gains `rules.specs`, `rules.tasks` and `operations.apply` / `operations.archive` guidance that points at the steps of `AGENTS.md` instead of restating them.
- The three over-long requirements (`button-pointer-states`, `textfield-placeholder`, `toolchain`'s structural search) are split the way the CLI prescribes: each keeps its header and scenarios with its text cut to one behaviour, and every behaviour cut out becomes its own requirement with its own scenario. Nothing they require changes.
- The archive is not repaired: the archived changes keep having no `.openspec.yaml`.

## Capabilities

### New Capabilities
- `openspec-tooling`: the pinned OpenSpec CLI, the skills generated by it and the CI check of the specs and changes.

### Modified Capabilities
- `button-pointer-states`: the requirement is cut to one behaviour, two requirements added for the rest; same behaviour.
- `textfield-placeholder`: the requirement is cut to one behaviour, two requirements added for the rest; same behaviour.
- `toolchain`: the structural-search requirement is cut to one behaviour, three requirements added for the rest; same behaviour.

## Impact
Infrastructure only: `openspec/`, `.claude/skills/`, `.agents/skills/`, `.github/workflows/ci.yml`, `AGENTS.md`. No library code.
