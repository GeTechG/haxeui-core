## Purpose
Fix the OpenSpec CLI version the repository runs, keep its skills generated by that version, and have CI reject specs and changes that break the OpenSpec rules.

## ADDED Requirements

### Requirement: The OpenSpec CLI version is pinned
`openspec/cli.pin` SHALL hold one line, the version of `@fission-ai/openspec` that every OpenSpec command of the repository runs with. CI SHALL run the CLI at that version through `npm exec --package=@fission-ai/openspec@<pin>`.

#### Scenario: CI run
- **WHEN** the `openspec` CI job runs
- **THEN** every `openspec` command it runs reports the version in `openspec/cli.pin`

### Requirement: The OpenSpec skills are generated by the pinned CLI
The repository SHALL commit the OpenSpec skills propose, explore, continue, apply, update, ff, sync, archive, bulk-archive and verify, generated by the pinned CLI, in `.claude/skills/openspec-*` and `.agents/skills/openspec-*`. The check SHALL fail when a skill's `generatedBy` differs from the pin or when there are no such skills.

#### Scenario: Stale skill
- **WHEN** `openspec/cli.pin` names a version and one `openspec-*` skill carries another `generatedBy`
- **THEN** the check fails and names that skill

### Requirement: A CLI bump is one commit
Moving to another OpenSpec version SHALL raise the global install first, then change `openspec/cli.pin` and regenerate the skills in a single commit. `AGENTS.md` SHALL describe that order.

#### Scenario: Bump
- **WHEN** the pin is changed to a new version
- **THEN** the same commit carries the skills regenerated by that version and the check passes on it

### Requirement: The specs and changes pass strict validation
The check SHALL fail when `openspec validate --all --strict` reports any issue for a main spec or an active change.

#### Scenario: Over-long requirement
- **WHEN** a main spec has a requirement whose text is longer than 500 characters
- **THEN** the check fails

### Requirement: A main spec has a real Purpose
The check SHALL fail when the Purpose of a spec under `openspec/specs/` starts with `TBD - created by archiving change`.

#### Scenario: Placeholder Purpose
- **WHEN** archiving a change created a main spec and left its Purpose as the placeholder
- **THEN** the check fails and names that spec

### Requirement: An active change has its metadata
The check SHALL fail when a change directory under `openspec/changes/`, other than `archive/`, has no `.openspec.yaml`. New changes SHALL be created with `openspec new change`, which writes that file.

#### Scenario: Hand-made change
- **WHEN** a directory `openspec/changes/<name>/` holds a `proposal.md` and no `.openspec.yaml`
- **THEN** the check fails and names that change

### Requirement: An archived change has no open agent task
The check SHALL fail when the `tasks.md` of an archived change has an unchecked task (`- [ ]`) that is not marked `[human]`. An unchecked `[human]` task SHALL pass.

#### Scenario: Forgotten task
- **WHEN** an archived change's `tasks.md` has the line `- [ ] 2.1 Run the typing check`
- **THEN** the check fails and names the file and the line

#### Scenario: Human step left open
- **WHEN** an archived change's `tasks.md` has the line `- [ ] 3.1 [human] Check the hover in the editor`
- **THEN** the check passes

### Requirement: The check runs in CI and before a push
`openspec/check.sh` SHALL run every check of this capability and exit non-zero when one fails. CI SHALL run it in its own job on every push to `master` and every pull request, and `AGENTS.md` SHALL list it among the checks run before pushing.

#### Scenario: Clean tree
- **WHEN** `openspec/check.sh` is run on a tree without defects
- **THEN** it prints `ok` and exits 0

### Requirement: The config carries the authoring rules
`openspec/config.yaml` SHALL give `rules.specs` and `rules.tasks` for the artifacts, and `operations.apply` and `operations.archive` guidance that refers to the steps of `AGENTS.md` instead of restating them.

#### Scenario: Spec instructions
- **WHEN** `openspec instructions specs --change <name>` is run
- **THEN** its output carries the `rules.specs` rules
